## 1. Native source vs Git: I was wrong to make Git the authority

My earlier line, "source stays in git," contradicted your native-first experiment. The revised position:

- **Native store is the authority** for any route that adopts it.
- **Git is an import/export edge.** Each route has exactly one authority, and there is no dual write.
- **Import must store the bytes natively.** The PRESERVATION rule ("a… hash or script is not proof that original archive bytes are in Git") applies in reverse too. A Git commit reference is not proof that native bytes exist.
- **Lossy round-trips must be explicit.** Snapshot currently excludes modes and symlinks. Git import should therefore either reject such trees or emit a recorded omission list. A silent round-trip loss would be a correctness bug, not a compatibility detail.

## 2. Accepted corrections

- **Adopting a protocol** is a versioned config or owner grant. Routine invocation under that grant needs no ceremony. Bootstrap authority lives outside the ledger.
- **Publish is not one operation.** It splits into store, replicate, discover/share, accept and activate. Unaccepted proposals can be shared.
- **Stale-context detection** covers only declared or indexable dependencies and known omissions. Borrowing from the Base12 map: only `requires` edges should propagate staleness, and `informs`, `contrasts`, `tests` and `motivates` should not. A truncated pack must mark dependency closure as *not established*.
- **No scheduler or router.** Portable execution metadata is recorded only.

## 3. The one invariant to add next: durable effect attempts

Your crash tests stop at the local commit/reply boundary. External effects need the same treatment before any networking exists.

**`Attempt(op_id, route, effect_digest, declared_endpoint, state)`**

- **States:** `Prepared → Dispatched → {Confirmed(receipt) | Failed(evidence) | Unknown}`.
- **Prepared** is written in the same transaction as the decision to dispatch.
- **Crash recovery** moves any `Dispatched` record to `Unknown`.
- **Unknown is never resolved by inference.** It leaves only through a new observation record, itself an untrusted EvidenceRecord.
- **Context rule:** a context pack for route R may not claim completeness while R has a non-terminal Attempt that the pack does not include. Omitted attempts must be listed as omissions.

This makes your concrete lost distinction a checkable state property rather than a convention.

## 4. Representation research as a test method, not a theory

The AI_NATIVE method can be applied directly: "find two fine descriptions that a proposed coarse description merges, then search for a future operation whose outcomes separate them."

- **The coarse description** is the context pack.
- **The fine descriptions** are ledger histories.
- **Context preparation becomes testable** against a corpus of *distinction pairs*. Each pair is two histories, an operation class and an expected action divergence.
- **A pack function passes** for a pair if it does not merge the two histories, or if it explicitly flags the merge as an omission.

Two limits keep this honest:

- **Sufficiency is relative** to the enumerated corpus and question set. There is no general sufficiency claim, and each new pair can reopen the result.
- **New formats must earn their place.** Any proposed pack format must show one of the listed advantages: reduced computation, an exposed invariant, a revealed omitted variable, unified calculations, or a new prediction. Novelty or a striking name does not count.

## 5. Falsifiable experiment

**Setup.** Two histories with identical Snapshot bytes:
- **History A:** push of X is `Unknown`.
- **History B:** push of X is `Confirmed`.

**P1 (deterministic).**
- The attempt-aware pack digests differ for A and B.
- A rule oracle yields "reconcile/observe remote" for A and "proceed" for B.
- A **source-only baseline** pack merges A and B.
- **Falsified if** the attempt-aware packs collide.
- **Uninformative if** the baseline already separates A and B.

**P2 (executor-level, separate claim).**
- Run N trials per executor under fixed declared settings.
- A should lead to reconcile at a pre-registered rate above B's rate.
- **Falsified if** the action distributions are indistinguishable at that threshold.

**Where it could legitimately fail:**
- If the remote effect is idempotent (for example, re-pushing a commit by hash), "re-push" is correct in both histories. The expected divergence disappears, and the pair is mis-specified.
- If the remote is unobservable, both histories may correctly lead to "observe first."
- If the pack budget drops the Attempt, the invariant has been violated, which is not the same as the pack being insufficient.
- Effects outside declared routes are outside scope by design.

## 6. Remaining overreach to challenge

- **"Authority" language is premature.** Acceptor IDs are unauthenticated namespaces, so Acceptances are *claims by a namespace* until authentication exists.
- **The protocol registry enforces nothing.** It is a set of digest-pinned Markdown documents the kernel does not execute, and should be described that way.
- **Agreement is not evidence of truth.** Multi-agent agreement does not establish source-invariant content (AI_NATIVE). Cross-review should count as independent checks, never as consensus weight.
- **"Ledger of accountable acceptance" was too narrow.** In a native-first design, exact byte custody is equally core.
- **Coverage claims stay partial.** Coordinator readings remain partial, and "a separate agent's full-source reading is not this agent's reading" applies to me as well.
