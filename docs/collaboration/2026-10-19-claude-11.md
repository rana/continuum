# Two Repairs and a Barrier Correction

## (A) Recovery safety

**Counterexample to my old criterion:**
1. Op X is submitted.
2. X commits durably.
3. The system crashes before replying.
4. Recovery restores X.
5. An exact retry returns X's original receipt.

X was never acknowledged, so "no unacknowledged outcome appears" wrongly rejects this correct trace.

**Corrected property.** Every recovered outcome must satisfy all of these:
- It matches an exactly submitted request.
- It is wholly present: head, generation effect, acceptance sequence, and receipt.
- It is either acknowledged or committed-but-unacknowledged.

Additionally:
- Every acknowledged outcome must be recovered.
- An exact retry of a recovered outcome returns its original receipt. A retry of a dropped, uncommitted operation executes fresh.
- Recovery must never produce an invented outcome, an outcome from a changed request, or a partial outcome (for example, a head moved without its sequence).

## (B) Honest classification

The implementation cannot see the oracle's acknowledgement schedule.

**Counterexample:** the last record was acknowledged, then a device fault flipped a bit in its final sector. On disk, this can be byte-identical to a torn, unacknowledged write. A checksum detects the damage but cannot tell which case occurred.

**Restated obligation.** The format must persist durable commit evidence, such as a synced boundary marker. The classifier then emits one of three results:
- **Clean.**
- **Torn tail:** damage lies strictly beyond the last verified durable boundary, so it is discarded.
- **Integrity-uncertain:** refuse and fail closed.

The oracle checks soundness: no image losing acknowledged data is ever classified clean or torn tail. Refusals are allowed, counted, and reported. Precision holds only under stated assumptions: the modeled fault classes and negligible checksum collisions.

## Barrier correction

Data is durable only after a completed barrier that covers it. Acknowledgement is issued only after that barrier completes. So, within the model, acknowledged implies durable.

## Effect on choices

- **Simulation-first: unchanged, and strengthened.** It enforces the separation between the oracle and recovery inputs, and it can enumerate the ambiguous images.
- **Emitted-verifier choice: unchanged in direction.** The verifier must now check these weaker, honest properties rather than perfect three-way classification.
