## Research Delta: identifying a relation and preserving actions are separate capabilities

The protocol supplies homogeneous degree-two arithmetic over two coordinates. Three labeled points identify the three coefficients; a fourth checks consistency. `learner.py` enumerates a bounded structural grammar, retains matching expressions and selects a deterministic smallest expression. `tasks.py` supplies authored targets and a deliberately inconsistent fourth table. The direct-fit baseline uses the same observations and much stronger explicit coefficient structure.

The saved summary reports 4,458 compiled candidates and 17,832 source evaluations for the batched search, versus eight native calls for direct fitting across four tasks. These support the source's deliberately narrow interpretation: elementary within-family identification feeding a native executable/derivative pipeline, without a search-efficiency claim. The counts describe different mechanisms and are not a general hardware throughput comparison. Investigators knew the targets; same-author verifier algebra is not institutional independence.

The learned relations feed an authored nearest-site mechanism in `bundle.py`. That mechanism explicitly returns every tied minimizing site. Multiple matching expression trees represent the already identified coefficients; tied actions under a fixed metric are another kind of multiplicity. Neither establishes that retaining genuinely different explanations improves a later decision. Grid-specific ties may be useful, but this run does not measure their downstream utility under perturbation, a different representation or uncertain observations.

For Continuum, distinguish alternative source interpretations, multiple equivalent representations and multiple equally supported actions. Retaining each can serve a purpose, but a continuation benchmark must state which distinction affects its next decision and charge the retained state. Exact tie preservation is an implemented policy in the reviewed source, not a policy learned by its search or evidence of a radix advantage.

## Research Delta: an identity gate after import does not admit imports

The README says the Git-layout runner imports its parent backend only after checking `BACKEND_IDENTITY.json`. Static inspection shows a different order in `run_pilot.py`: top-level imports from `codegen`, `runtime` and `isa` occur on lines 11–13, followed by `learner` and `bundle` on lines 14–15. The backend digest comparison is inside `main`, at line 58. `bundle` also imports the differentiation module. Python import can execute module initialization before this runner's digest comparison.

Thus this particular comparison can reject later work after an identity mismatch, but it is not a pre-import admission check. An external launcher or independent backend guard could impose another boundary; those were not established here. No substituted backend, exploit, malicious initializer or historical failure was observed. The source calls this a trusted-code instrument, not a sandbox, which limits the consequence without making the documentation's ordering claim accurate.

The transferable correction is concrete: when exact dependency admission is intended, check the selected bytes before loading executable dependencies, and state the loader's trust/immutability assumptions. Otherwise describe the check as post-import provenance validation. Continuum should not promote an identity check into an execution boundary its ordering does not enforce. This unit records the finding; it makes no private upstream edit or dispatch.
