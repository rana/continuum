## Research Delta: reservation has a narrower guarantee than durable exactly-once execution

The launcher checks its location, frozen inputs, tools, architecture and CPU affinity before reserving the named attempt. It rejects existing attempt-prefix entries and uses atomic directory creation for the actual reservation. Reservation precedes the consumed marker and monitored child; noclobber protects subsequent evidence writes. A preflight failure can therefore leave the attempt unconsumed, while a failure after reservation leaves the directory reserved even if later evidence is incomplete.

These are useful cooperative admission rules under trusted filesystem/tool assumptions. The prefix scan alone is not the concurrency fence; directory creation supplies that fence for the exact same path. Marker and directory writes have no explicit fsync, authenticated ownership protocol or atomic multi-file commit. Source order does not establish crash-durable exactly-once state, resistance to deletion/reuse, or absence of concurrent path mutation. No such race or crash was tested here.

The externally supplied freeze digest avoids asking the launcher to trust only its own mutable manifest. Verification still reopens paths through trusted utilities. Matching digests for the two scripts and manifest supply actual text custody; neither historical tool output nor this review supplies new executable-binary custody.

## Research Delta: completion depends on explicit checks and shell control flow

The driver verifies that its parent is the expected timeout monitor and checks process group/session relationships before native invocation. Its EXIT trap records status and kills the kernel's current group on failure, including a failed status write. This differs from killing a remembered numeric group after the monitor has been reaped. The launcher instead performs a read-only post-wait scan, checks saved boot/namespace context and rejects observed members or persistent unreadable process entries. A vanished process directory is treated separately. The saved no-members result remains a snapshot; the source does not turn it into a current census or hostile-interference guarantee.

The normal case loop captures the native exit and prints it before checking the expected exit. The twelve literal fault-injection specifications derive exactly the twelve saved fault names and expected exits. Directory checks count all entries and require each expected regular, nonsymlink file; failed cases must leave no destination, and staging-prefix checks include other entry types.

The collision path captures and requires exit three, preserves the sentinel, requires it to be the only entry and checks staging absence before the synthetic/fault-gate marker. The retained path follows that marker, checks input metadata/digests, invokes the native decoder under shell errexit, compares both output files and checks exact directory/staging contents before retained completion. This explains the previous receipt return's two outcomes without inventing two additional printed verdict rows. It remains reasoning from frozen Bash control flow and saved receipts, not a fresh native execution or dynamically exercised signal, timeout, failure-cleanup or crash test.
