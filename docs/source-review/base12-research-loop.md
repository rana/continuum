# Base12 research loop: from discrepancy to reproducible evidence

This review follows one native consumer from its mathematical question through reduction, replay, external auditing, and a proposed build boundary. The most useful design lesson for Continuum is that **a witness is a claim with an explicit scope and a recoverable evidential history**. Its input, arithmetic semantics, preserved failure class, search neighborhood, completion condition, and execution provenance all matter when another agent resumes the work.

## 1. Preserve the question that makes a witness meaningful

The selected consumer evaluates three fixed source/target pairs at scale 12: repeated halving, exchanging the order of division by two and three, and canceling an addition followed by subtraction. Inputs are integer coefficients in `[-36, 36]`; values represent those coefficients divided by 12. Rounding occurs after the specified primitive operations, and an intermediate result outside the range produces a defined fault. The executable accepts rule identifiers for those fixed graphs. It does not accept a new AST, arbitrary rewrite, or general instruction stream. Both input coordinates must satisfy the admission contract even when a selected graph uses only one. [Consumer contract](https://github.com/rana/base-12-ai/blob/88382e793b65c84fd8e223840c27f6bb8682864a/research/owned-stack/2026-10-16/native-research-loop/CONSUMER.md)

This gives three different kinds of failure that an agent must keep separate:

| Observation | Meaning for the investigation |
|---|---|
| Two correctly evaluated programs return different values or differ in defined-fault behavior | A semantic counterexample to that proposed relationship. For two of the chosen rules, this is the intended negative control. |
| The native program disagrees with the independent mathematical oracle | An implementation or specification discrepancy requiring investigation. Shrinking must not silently relabel it as the intended rewrite counterexample. |
| Framing, domain admission, I/O, terminal status, or capture fails | The attempted execution does not establish an accepted semantic result. Preserved partial output can still be diagnostic evidence. |

The source explicitly separates these cases. It also separates the name of the first violated semantic contract from a claim to have located the first faulty machine instruction. A range-preservation witness explains what property failed; source maps and lowering analysis answer a different question about where an implementation diverged. [Witness and replay specification](https://github.com/rana/base-12-ai/blob/88382e793b65c84fd8e223840c27f6bb8682864a/research/owned-stack/2026-10-16/native-research-loop/WITNESS_REPLAY.md)

For Continuum, a context bundle should preserve the disputed proposition and its assumptions beside the observed bytes. “The test failed” loses whether the program detected an intentionally invalid rule, implemented the intended rule incorrectly, or never completed a valid observation. Those interpretations lead to different next actions.

## 2. A reduced witness needs an exact reduction contract

The reducer fixes the rule, semantic version, scale, admitted domain, and original mismatch class. Its candidates may change one coordinate at a time. It orders eligible pairs by `K(x,y) = (|x| + |y|, |x|, x, y)`, considers only strictly smaller keys, retains the first candidate preserving the original mismatch class, and restarts the neighborhood from the retained pair. Every evaluated candidate and its retain/reject decision is represented in the event stream. [Reduction contract](https://github.com/rana/base-12-ai/blob/88382e793b65c84fd8e223840c27f6bb8682864a/research/owned-stack/2026-10-16/native-research-loop/WITNESS_REPLAY.md)

The stopping result is deliberately precise. A completed pass supports a **one-coordinate minimum under that neighborhood**. A candidate pass stopped at the evaluation allowance can report a replayable witness after the required final reconfirmations, without establishing minimality. This protocol's budget exhaustion is a normal completed result; an external interruption with partial output has a different status. The independent auditor reconstructs the eligible ordered set itself, verifies the visited prefix and first retention, and checks the restart and stopping reason. A reducer's final “minimum” flag cannot supply the missing search evidence. [Auditor source](https://github.com/rana/base-12-ai/blob/88382e793b65c84fd8e223840c27f6bb8682864a/research/owned-stack/2026-10-16/native-research-loop/implementation-01/audit_stream.py)

A useful source-derived counterexample to an overbroad summary appears in the hand expectations. For cancellation, both `(-36,-1)` and `(-1,-36)` make the intermediate sum `-37`, preserving the original-fault/target-value mismatch. Each is locally minimal under the allowed one-coordinate moves, although `(-1,-36)` has a smaller global key. A handoff that remembers only “the minimal witness” would erase the qualification that makes the result true. These are mathematical examples from the inspected source, not newly executed observations. [Hand expectations](https://github.com/rana/base-12-ai/blob/88382e793b65c84fd8e223840c27f6bb8682864a/research/owned-stack/2026-10-16/native-research-loop/implementation-01/EXPECTATIONS.md)

This suggests a reusable Continuum object containing the original artifact, retained artifact, preserved predicate, transformation neighborhood, ordering rule, observed prefix, and completion reason. It could support code reduction, prompt reduction, failing deployment configurations, or a smaller distributed schedule. Each application must define which property the reduction is allowed to preserve; a smaller artifact alone is not enough.

## 3. Reserve evidence completion within the work budget

SEEK permits at most 256 paired evaluations, including the original seed and two final reconfirmations. Candidate work checks the counter before the next eligible evaluation and reserves those last two evaluations for reconfirming the retained pair. REPLAY performs one paired evaluation. The fixed wire format admits a 128-byte header, at most 256 event records of 64 bytes, and a 256-byte final record: at most 16,768 output bytes. [Wire and budget contract](https://github.com/rana/base-12-ai/blob/88382e793b65c84fd8e223840c27f6bb8682864a/research/owned-stack/2026-10-16/native-research-loop/WITNESS_REPLAY.md)

The boundary has a subtle consequence: reaching the candidate allowance does not automatically make a result incomplete. If the final eligible neighbor has already been evaluated and none remains, the pass can be complete at that boundary. If an eligible neighbor remains, the only supported result is budget-exhausted and replayable. The stopping reason depends on the actual frontier, not solely on a counter comparison. [Static review](https://github.com/rana/base-12-ai/blob/88382e793b65c84fd8e223840c27f6bb8682864a/research/owned-stack/2026-10-16/native-research-loop/implementation-01/STATIC_REVIEW.md)

The corresponding design opportunity is to budget for obtaining a trustworthy result, including its reconfirmation and evidence completion. A scheduler can distinguish work that found a useful candidate, work that completed its promised coverage, and work that secured the observations required to support a claim. A canceled search can contribute its captured prefix without receiving a completion claim.

The reported consumer evaluation count also has a specific accounting boundary. The external auditor performs its own mathematics and neighborhood checks; its effort is additional work. Native instruction count, semantic evaluation count, verification cost, captured bytes, elapsed time, and model effort should remain distinct measurements. The source's order reconsideration explicitly keeps the external Python auditor and review costs visible and makes no end-to-end speed claim. [Order reconsideration](https://github.com/rana/base-12-ai/blob/88382e793b65c84fd8e223840c27f6bb8682864a/research/owned-stack/2026-10-16/native-research-loop/implementation-01/ORDER_RECONSIDERATION.md)

## 4. Bounded arithmetic does not bound waiting or establish cancellation

The consumer reads exactly one request and then requires EOF on an additional one-byte probe. It handles short I/O and retries interrupted reads or writes. Its contract explicitly leaves those retries externally budgeted and leaves process supervision to an external caller. [Consumer I/O contract](https://github.com/rana/base-12-ai/blob/88382e793b65c84fd8e223840c27f6bb8682864a/research/owned-stack/2026-10-16/native-research-loop/CONSUMER.md)

A source-derived operational witness makes the distinction concrete: supply the full valid request through a blocking pipe but keep the writer open. The consumer cannot yet observe the required EOF. Its finite input size and evaluation allowance do not establish a finite wall-clock completion time. Interrupted or blocked output creates a related boundary. This is an inference from the stated I/O contract; no process was run to demonstrate it here.

The proposed build envelope separately identifies CPU affinity, per-process address-space and CPU limits, a kill watchdog, and outer aggregate CPU/wall acceptance budgets. It acknowledges the trusted outer setup and accounting were still to be materialized at that checkpoint. Per-process restrictions, whole-attempt accounting, watchdog behavior, and durable evidence publication are different obligations. The packet is not evidence that those proposals were exercised. [Build review](https://github.com/rana/base-12-ai/blob/88382e793b65c84fd8e223840c27f6bb8682864a/research/owned-stack/2026-10-16/native-research-loop/implementation-01/BUILD_REVIEW.md)

For multi-workstation work, cancellation should therefore name its scope and observed outcome: a request was issued, an executor stopped, descendants were accounted for under a stated process model, or partial evidence was preserved. A canceled controller does not by itself prove every external activity stopped. A context handoff should retain which of these events was actually observed, together with any remaining uncertainty.

## 5. A correct stream is one component of execution evidence

The external auditor uses a different formulation from the native consumer: exact rational arithmetic with floor quotient/remainder rounding, and set-union plus sorting for the neighborhood. It checks the request echo, every event, the mathematical outcomes and classes, and all final bytes, including reserved fields. Its final record is reconstructed from the auditor's own traversal. The source also states the limits of this independence: the same worker authored both formulations, and both depend on the declared mathematical specification. [Auditor](https://github.com/rana/base-12-ai/blob/88382e793b65c84fd8e223840c27f6bb8682864a/research/owned-stack/2026-10-16/native-research-loop/implementation-01/audit_stream.py), [independence boundary](https://github.com/rana/base-12-ai/blob/88382e793b65c84fd8e223840c27f6bb8682864a/research/owned-stack/2026-10-16/native-research-loop/implementation-01/EXPECTATIONS.md)

Its CLI accepts a terminal-exit integer from the caller. Requiring that integer to equal zero checks the supplied claim; it does not attest to the actual process outcome. An invented stream that satisfies all mathematical and structural checks would establish internal conformity of those bytes, while still lacking evidence of which executable produced them. The source explicitly requires a separately trusted capture to bind actual command, artifact identity, and terminal status. Its bounded regular-file reads constrain input handling, but they do not create execution provenance. [Auditor acceptance boundary](https://github.com/rana/base-12-ai/blob/88382e793b65c84fd8e223840c27f6bb8682864a/research/owned-stack/2026-10-16/native-research-loop/implementation-01/EXPECTATIONS.md)

Continuum should consequently preserve a graph of claims and their evidence producers. A semantic checker supports a mathematical or structural conclusion; a trusted executor supports a run-identity and terminal observation; an acceptance authority evaluates whether those bindings satisfy the relevant policy. A model review can identify a missing obligation, but agreement between reviewers supplies neither a new execution nor an independent measurement.

Reconfirmation and replay have equally specific value. Repeated evaluations test the promised consistency of this run; a fresh process can test the declared replay contract. They are not automatically independent samples of a stochastic phenomenon. A replay identity should bind request, semantic version, implementation, expected class, and the execution conditions relevant to the claim. Mode-specific framing can differ while the defined semantic result agrees. [Replay specification](https://github.com/rana/base-12-ai/blob/88382e793b65c84fd8e223840c27f6bb8682864a/research/owned-stack/2026-10-16/native-research-loop/WITNESS_REPLAY.md)

It does not require discovery of a previously unknown bug to justify a reliable instrument. ## 7. Context that preserves these distinctions

The following are proposed adaptations for Continuum, derived from this review rather than claims about implemented Continuum behavior:

| Context item | What a successor agent needs to recover |
|---|---|
| Question and semantic scope | Exact proposition, graph/version identity, admitted inputs, rounding and fault semantics. |
| Original and retained witness | Both artifacts, the preserved mismatch predicate, and the ordering and neighborhood used to reduce them. |
| Search and completion evidence | Visited prefix, retention/restart decisions, resource boundary, reconfirmations, and the precise minimality or incompleteness claim. |
| Checker result | Exact bytes checked, checker identity, formulation, shared dependencies, and what its verdict establishes. |
| Execution and cancellation | Actual executor/artifact/request identities, observed terminal state, capture publication, cancellation scope, and unresolved effects. |
| Historical stage | Which source, build, run, or acceptance checkpoint produced a statement and what later evidence supersedes its status. |

This context can make an ambitious native repository useful before it becomes a general optimizer or distributed runtime. An agent can recover why a failure matters, which interpretation remains open, and the next discriminating experiment. Later semantic generators and guarded-rule discovery can build on the same evidence objects. A small validated witness becomes a reusable research asset whose meaning survives a new chat or workstation.
