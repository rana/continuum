# Protocol registry

These versioned, agent-guided procedures help a worker select a useful method and leave an inspectable receipt. They are not installed slash commands, schedulers, or permission grants.

| Protocol | Use |
|---|---|
| [Progress Brief](progress-brief.md) | Restore orientation from actual evidence and identify the next useful action. |
| [Holographic Walk](holographic-walk.md) | Investigate a bounded question across representations and return with a changed constraint or better question. |
| [Research Record](research-record.md) | Preserve a substantive contribution, its evidence, and actual coverage. |
| [Bounded Research Loop](bounded-research-loop.md) | Continue an authorized objective through useful units and recoverable handoffs. |

[registry.json](registry.json) records exact definition versions and SHA-256 digests of the Markdown bytes. It is discovery metadata, not a second copy of each procedure. The registry, invocation, and receipt schemas are under [schemas](../schemas/).

Start with one applicable method. Compose another for a named missing function, with a finite budget. Unneeded procedures can be skipped. Read the [architecture contract](../docs/architecture/protocols.md) for precedence, versioning, and effect boundaries.

Examples under [examples](examples/) are synthetic fixtures, not records of actual runs. Editing a definition requires a deliberate version/revision decision and refreshing its digest; old invocation receipts continue to reference the exact earlier content. No registry entry claims that the native executable currently runs the procedure.
