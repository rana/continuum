# Bounded Research Loop

**Protocol:** `bounded-research-loop@0.1.0`  
**Mode:** agent-guided continuing research  
**Invocation:** “Continue the research.”

## Purpose

Advance an authorized continuing objective through useful, bounded units. Bound the current unit without treating an arbitrary number of turns, checks, or passes as the end of the program.

This procedure selects work inside an existing grant. It does not create authority, recurrence, spending capacity, credentials, or a worker.

## Inputs and selection

Read the current user direction, project mission and governing instructions, the relevant exact source snapshot, actual task ownership, previous attempt records, available resources, and remaining questions.

Select a unit that can improve understanding or unlock another investigation: source recovery, derivation, interface design, implementation, model comparison, an experiment, a review, or a free imaginative seed. Prefer the smallest useful result over administrative expansion.

Name the question, desired contribution, available inputs, accountable owner where needed, resource bound, and stop condition. For a test or execution, also declare the expected observation and acceptance criterion. An imaginative seed can remain a question or candidate object without either. Reuse an established run envelope when it still applies. Do not rebuild approval machinery for every call.

## Work cycle

1. **Orient.** Recover facts and actual access; distinguish a declared capability from measured availability.
2. **Choose.** Select an actionable question and identify what evidence could change the decision.
3. **Investigate.** Read original sources, work through the derivation, design or implement, and compute where it resolves a concrete uncertainty. Preserve assumptions and actual scope.
4. **Challenge.** Seek a useful independent perspective or evidence path. Distinguish model disagreement from empirical contradiction. Preserve shared sources and correlated assumptions rather than calling every additional worker independent.
5. **Evaluate.** Assess the contribution against its stated purpose. For an experiment, compare the result with the predeclared criterion. For an imaginative unit, preserve a useful question or candidate without inventing a pass/fail result. Report negative outcomes, uncertainty, and counterexamples as faithfully as positive ones. Do not retrospectively change an evaluation to make it pass.
6. **Preserve.** Apply `research-record` to the consequential unit and update the same authoritative work records.
7. **Continue.** Choose the next ready unit or leave a durable handoff for an actual successor.

A walk can be composed when a representation or interface mismatch is material. A brief can be composed when a person needs orientation. Neither is mandatory after every unit.

## Ownership and capacity

Isolate concurrent edits and reconcile overlapping authority surfaces. An offered handoff is not received or accepted work. Require recipient-authored acknowledgments for those statuses. A current owner can delegate disjoint contributions without becoming a gate on all independent thought.

For shared execution, distinguish resource reservations, execution receipts, and live telemetry. Use fencing only where the actual effect recipient supports it; a local lock is not a distributed guarantee.

Respect available compute and spending bounds. A blocked dependency does not freeze unrelated useful work. Diminishing returns call for a changed question, observation, or representation. Constant activity and large commit counts are not the objective.

## Interrupted, failed, and superseded work

Preserve the exact prior attempt and its outcome. A historical failure remains evidence about that attempt. A separately identified corrected successor can proceed when current authority and readiness permit it.

A timeout does not determine whether an effect occurred. Reconcile saved receipts or the effect recipient before retrying. Cancellation requested and cancellation completed are distinct. Preserve completed useful observations even when responsibility moves.

Continue during supported active turns. At a boundary, leave a sufficient checkpoint and next action. This document does not wake dormant chats, install an agent, or guarantee activity between turns.

## Output and completion

A unit receipt identifies actual inputs, performed work, results and limitations, consumed resources when observed, and the next action. The continuing objective completes according to its acceptance contract or explicit user direction, not a quota of protocol invocations.
