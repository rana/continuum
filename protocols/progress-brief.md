# Progress Brief

**Protocol:** `progress-brief@0.1.0`  
**Mode:** agent-guided procedure; not an installed command or scheduler  
**Invocation:** “Give me a progress brief.” Optional: brief, deep review, read aloud, since the last brief.

## Purpose and applicability

Restore orientation, explain consequential change, expose uncertainty, and identify the next useful action. A brief is a dated projection of evidence, decisions, and work records. It is not a second live task board.

Use this procedure for an explicit status request or a selected substantive milestone. A quiet interval can warrant a short honest update; it does not require a new experiment, collaborator call, or archived commit.

## Inputs

Required: the current objective and governing instructions, an exact accessible source snapshot, a concrete evidence cutoff, and the relevant evidence and task records. Optional: a previous brief, capacity observations, current review discussions, and actual collaborator contributions.

Record missing access. If there is no usable comparison baseline, produce an orientation brief. Do not invent a delta or assume a 24-hour window.

## Procedure

1. **Pin the view.** Record the input revision or supplied-file identities, UTC cutoff, local timezone where useful, and previous baseline. A source hash identifies content; it does not establish that missing bytes were preserved.
2. **Reconcile the important changes.** Read original evidence and actual owner or acceptance records for consequential claims. Resolve apparent contradictions by identity, scope, authority, and chronology. A newer proposal does not supersede stronger evidence solely because it is newer.
3. **Distinguish kinds of progress.** Name what was proposed, implemented, built, executed, tested under scope, reproduced, accepted, and published. These can apply to different objects and are not a single irreversible ladder. A built program has not necessarily executed.
4. **Explain the change in understanding.** Include useful failures, corrected assumptions, rejected alternatives, and promising unfinished questions. Separate observation, interpretation, prediction, and decision.
5. **Assess capacity from evidence.** Distinguish declared availability, verified reachability, reservation, historical execution, and measured utilization. Unknown current activity remains unknown. Task ownership, recent commits, or a powered machine do not establish saturation or continuous work.
6. **Collaborate when useful and available.** Supply the relevant visible request and evidence to an actual counterpart. Record what was supplied and whether a response completed. Preserve material corrections and disagreement. Unavailable or failed consultation does not prevent independent useful work.
7. **Select the next horizon.** State the immediate selected step, the next promising investigation, and the longer capability they could enable. Name dependencies and completion conditions; avoid invented dates or guarantees.
8. **Preserve the useful result.** Save a compact dated report when requested or when the result merits preservation. Update an authoritative task or decision record only if its owned fact changed. Reconcile a material late change without indefinitely chasing unrelated updates.

## Output

Lead with a short judgment, followed by connected prose suitable for the requested audience. Cover actual results, what changed in understanding, the strongest counterweight, current uncertainty, capacity where relevant, and the next action. Select a few questions that can change the work.

Place evidence references near factual claims. Keep dense identifiers in a written evidence section when a spoken rendering would become difficult to follow. Typed fields may be checked mechanically; interpretive prose remains synthesis rather than mechanically certified entailment.

The invocation receipt records the input snapshot and baseline, actual reading and collaborator exposure, output references, limitations, and effects performed.

## Stop and recovery

Stop when the requested orientation is restored or the remaining gap requires unavailable evidence. Record partial coverage honestly. An unavailable baseline is a reason to produce an orientation brief, not a reason to stop all useful work.

Do not rerun an experiment merely to make a brief fresher. Reconcile an uncertain effect before retrying. No report invocation creates a new timer, worker, grant, or approval obligation.
