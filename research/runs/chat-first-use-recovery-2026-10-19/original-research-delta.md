**New finding from contract inspection.** The native `matches_at_observation` freshness state compares a recorded acceptance anchor against an accepted **SQLite head**. It does not automatically compare a live Git worktree or remotely accepted Git commit to source object identity. Editing `CURRENT.md` outside the Continuum store can leave the old SQLite head unchanged, so a pack can still report a matching native anchor while the checkout has drifted. This is not a defect in the documented local contract; it is a consequential integration boundary to make explicit before using the tool operationally. Also, the rendered context contains source-object references, not the bytes of all source files; a recipient without access to those blobs cannot recover the actual source from their hashes alone.
