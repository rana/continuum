# Research Delta — promote an owned authority target

**Question.** Rana renewed the original open, AI-native scientific code repository mission and asked whether Continuum currently owns storage, whether a clean-slate stack should own it, and whether Rust/SQLite had become a permanent direction. This unit makes the development-target decision explicit rather than leaving ownership indefinitely as an optional research response to a speed bottleneck.

**Owner and baseline.** Chat research coordinator, public `rana/continuum` main `c474b0dc9e6f4732d22a1c3f2f4da20df415a2cd`, UTC 2026-10-19. The current `Cargo.toml` directly depends on `rusqlite 0.40.2` with bundled SQLite. `src/store.rs` defines SQLite `objects`, `heads` and `events` tables with local transactions, WAL and FULL synchronization; it does not implement its own pager/journal/recovery. `CURRENT.md`, `AGENTS.md`, `docs/operations/continuation.md`, ADR 0001/0002, mission, current owned-native design and real-use packet status were read from this pinned revision. An open PR #110 owns the current real-use receiver/recorder, with an actual uncertain provider response; this unit never repeated that invocation.

**Change.** [ADR 0003](../../../docs/decisions/0003-owned-authority-development-target.md) selects the AI-native scientific code/investigation repository as the product and a minimal **project-owned append-only persistence authority** as the *next development target*, written initially in Rust. SQLite stays the operational reference; no store switch is adopted. Exact acceptance semantics, application-layer evidence/scope, source editing, external authority and effect confirmation remain distinct. The first unit is finite modeling and independent oracle, then disposable shadow bytes and fault/recovery comparisons, then a small real-source scientific continuation with a good notes control. No custom engine, migration, rename, user-workstation installation, code execution or new scheduler is claimed.

**Original evidence and checks.** Repository API read of main ref; pinned `fetch_file` of `Cargo.toml`, `src/store.rs`, `CURRENT.md`, `AGENTS.md`, `MISSION.md`, `docs/operations/continuation.md`, ADR 0001/0002, owned-core design and relevant real-use Research Delta; `compare_commits` from `416e41f` to `c474b0dc9e` for release/bridge-only material; `fetch_pr` and `fetch_pr_comments` of open PR #110, plus stale owned-journal branch refs. No Rust toolchain is installed in this task container, and a direct `git ls-remote` failed due DNS: tests, binaries and CI for an owned kernel were **not** run here. This is a source-based design decision, not a performance or durability result. The exact supplied-context Claude response is preserved in `claude-review.json`; it is a critique rather than independent empirical proof. GitHub publication/CI, if completed, are separate evidence.

**Negative findings/corrections.** We currently own semantics, not the SQLite physical storage layer. A repository rename would not fix that. Existing owned-journal branch names do not establish an active accepted implementation. A single append and checksum cannot establish atomic acknowledged recovery or distinguish every truncated tail from damaged acknowledged bytes. A perfect match among three checkers with shared erroneous assumptions can miss a bug. A shared operation key does not prove remote provider finality or replay safety. Claude's suggested two-state old/new recovery verdict is incomplete under integrity uncertainty, and its definite 'never committed' response is not always available from corrupted evidence; qualify both. Rust native compilation is not ownership of instruction emission/OS/runtime services.

**Uncertainty.** Framing version, commit-boundary selection, writer takeover, directory sync, fault model and backup/upgrade behavior are still proposals. The value of custom persistence versus good SQLite and Git/Markdown remains unmeasured; the first real-use study has not produced an accepted receiver/scorer outcome. The current desktop worker remains independently active; do not infer its status or receipt from Git commits or lease timestamps.

**Next actual owner.** No downstream code worker has accepted. The next authorized code-capable Continuum implementation worker, after checking actual ownership, should audit any current owned-storage model branch, implement/verify the bounded finite oracle and deliberately wrong mutants in disjoint `research/owned-authority/` paths, then demonstrate a minimal disposable Rust journal without importing SQLite as an authority. Completion requires exact inputs, test output/counterexamples, independent recovery verdicts, and no effect on retained stores. Current PR #110 remains with its existing owner; there is no automatic dispatch.
