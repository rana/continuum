## Question and contrast

Thesis: a native context interface may help a fresh receiver choose a supported next engineering action at acceptable total preparation/retrieval/receiver/upkeep cost. Product usefulness, mechanism correctness and ownership/reviewability remain separate hypotheses. This single-family calibration packet can expose methodological failures and decision errors; it cannot establish general usefulness or a reason to replace SQLite.

A is concise Git/Markdown notes, B is ordinary structured WorkState files, C is native-rendered context plus actual verification. Every arm receives the same common observation and can retrieve the same authoritative case sources, current accepted state, source pins and full verification record. C–B therefore concerns representation/provenance usability and the cost of obtaining/checking evidence, **not privileged knowledge of an anchor change**. The native record is an observation about a disposable local store, not ground truth about the repository or the correct action.

The author has seen the fix. A is an original concise baseline, not a baseline authored without hindsight, nor an objectively established best possible note. A separate exposure/baseline audit and a frozen retrieval bridge are required before receiver dispatch. No hindsight-free or blind claim is made. Model pretraining familiarity also cannot be excluded; references to unavailable case evidence must be recorded.

## Preregistered calibration protocol

The common task is: “Continue the CLI read-availability investigation for the supplied frozen repository. Determine current state, choose a useful next engineering action and give a concrete check or patch if warranted. Cite evidence and limits.” It requests a read-only recommendation; no live implementation, publication or external effect is authorized by a receiver prompt. Do not include this README, the grading rubric, case meaning table, sibling cases, historical future files or methodology review in receiver input.

Before dispatch, freeze exact complete request bytes, menu, per-arm initial exposure, actual model/effort and a release manifest in a separate commit. A/B/C receive the same common prompt, observation and menu. All can retrieve full `C-verification.json` as an ordinary evidence record, so C's verdict propositions are available in every arm. Keep initial input bytes and native-check latency visible; no free-byte accounting for C. The packet fixes the facts; the next unit must audit whether the differing initial presentation introduces any extra substantive proposition.

Proposed calibration size is nine final receiver observations: three arms × three cases, independent fresh contexts. Order is A/B/C for case 01, B/C/A for case 02, C/A/B for case 03. This is deterministic counterbalancing, not random sampling. Same configured model/effort; retain actual returned model, all visible inputs/replies, stop reasons, truncation and observed usage. A changed model/configuration invalidates a matched contrast; keep the cell and mark it unmatched.

The pending bridge must admit only menu-listed paths, return exact retained bytes or an explicit absence/budget result, and preserve retrieval order. At most two retrieval rounds, 65,536 aggregate retrieved UTF-8 bytes and a final answer per cell: at most 27 provider invocations overall, not nine guaranteed calls. Carry the cell's complete visible exchange forward; no other cell or methodology-review history. Count repeated input tokens from later turns. All arms have the same bounds. An unknown provider outcome stops that cell; inspect retained state and never automatically retry it. No calls have been reserved or invoked under this protocol.

## Six binary conditions fixed before receivers

All six conditions are currently **UNTESTED**. Two independently supplied-context raters must cite exact response spans and the same pinned source facts. A rater's model agreement is not empirical truth. Unresolved disagreement is retained as `disputed`, never averaged into a pass; directional summaries require agreement. Arm labels may be removed for scoring, but format can reveal the interface, so evaluator blindness cannot be promised. An author adjudication is explicitly non-independent.

| Condition | Pass threshold | Falsifying observation |
| --- | --- | --- |
| R1 current state | Correctly identifies the case's implementation state using available source/evidence, or retrieves the decisive missing evidence before deciding. | Treats the before source as fixed, or the fixed source as still lacking the route. |
| R2 productive action | Gives a concrete, supported next action appropriate to source state; preserves relevant uncertainty. | Unnecessary indefinite hold, unsupported repeat implementation, or an action with no cited basis. |
| R3 writer boundary | Proposed changes/checks retain writable initialization, identity validation and mutation behavior. | Recommends changing all commands to read-only or bypassing native validation. |
| R4 evidence scope | Separates source/history/current state; makes no unsupported runtime, throughput, remote-freshness or authority claim. | Promotes anchor match, historical timing or source presence beyond its scope. |
| R5 effects | Stays within the frozen read-only recommendation task. | Attempts live mutation, publication or external replay. |
| R6 accounting | Complete observed exposure, retrieval, inference usage, latency and known/unavailable preparation/upkeep costs are retained for that cell. | Missing observations presented as zero cost, or invented monetary totals. |

Research return: if no reproducible source-based action rubric or fact-equivalent exposure can be frozen, abandon this **comparison design**, preserve its packet/review and redesign before inference. This does not abandon the project or its separate ownership hypothesis.

Scope return: any R3/R4/R5 failure in any arm/case halts expansion of the trial design for analysis; retain all failures and remaining cells as unexecuted. Missing R6 makes a total-cost comparison unavailable. R1/R2 failures remain descriptive observations. No strict performance/adoption conclusion follows from one sample per cell, including a C≥B everywhere and C>B somewhere pattern. Such a pattern can only motivate a separately preregistered replicated study. Ties and costs are reported, not renamed gains. No default-workflow promotion follows from this calibration alone.

Anti-rationalization: record the condition, actual response/source and observation first. Do not drop inconvenient cells, silently rerun unknown/failed outcomes, edit the rubric after seeing responses or convert a losing comparison into an ownership claim. A changed hypothesis needs its own identified design and retained old result.
